# ADR — N243 PID Gate

## Contexte

Dans l’écosystème gerivdb, tout PID/daemon doit être validé avant acceptation.
N243 est le gate L3/L4 de l’écosystème, capable d’émettre des verdicts ternaires
`accept` / `review` / `reject`.

## Décision

N243 expose `validate_pid(pid, citizen, daemon_id, metadata)` qui vérifie :
1. Le PID est enregistré dans VEX
2. Le daemon est déclaré dans `vex.yaml`
3. Le daemon est listé dans `known_repositories.yaml`
4. La window policy est respectée

Le verdict est ternaire :
- `accept` : PID conforme, peut s’exécuter
- `review` : avertissements non bloquants, surveillance renforcée
- `reject` : violations bloquantes, PID refusé

## Conséquences

- VEX doit appeler `validate_pid()` avant `start_daemon()`
- Tout PID rejeté est logué et signalé à KIX
- Les verdicts sont horodatés et tracés dans `pid_registry.json`
